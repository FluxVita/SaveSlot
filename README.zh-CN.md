# SaveSlot

[English](README.md) · **简体中文**

### 记得住，不代表记得准。

**上下文会腐烂，AI 做事更要心中有数。**

持续掌握目标、约束与执行进展，分清已确认、待核实和存在冲突的信息，不让旧判断影响下一步。

技术定位：开源 Personal Agent State Layer，产品核心是 Trusted State View（可信状态视图）。SaveSlot 旨在 Agent 执行全程持续跟踪、更新、验证和检索当前状态，返回紧凑视图，每项都带来源、依据、时间、版本、权限和明确的可信度标记。

> 🚧 **早期阶段。** 以下内容描述的是产品方向，所有能力均为**规划中**，实际状态以[能力矩阵](#能力矩阵)为准。

## 同一个 Session 里，状态就会失真

一个 Agent、一个长任务。没有可信状态视图时，常见三种问题：

| | 发生了什么 | Trusted State View（目标体验） |
|---|---|---|
| **约束改了** | 先前：“给所有用户加订单导出功能。”<br>后来：“改成只有管理员才能导出。” | **Confirmed**（用户确认）：仅管理员可导出。<br>旧约束标为已替代，保留时间和版本。 |
| **工具结果不确定** | “部署 v2 版本。”<br>工具：请求超时，无法确认是否成功。 | **Unknown**：部署结果未知。<br>下一步：向部署系统核验，不直接标为完成。 |
| **证据冲突** | 任务系统：“已完成。”<br>测试系统：“关键测试仍未通过。” | **Conflicted**：保留双方来源和时间。<br>不擅自覆盖，先确认再行动。 |

<sub>以上为目标体验示例，不表示所有现有 Memory 产品都会犯这些错误。</sub>

**记住过去，不等于掌握现在。** 心中有数，就是在下一步行动前分清哪些已确认、哪些是推断、哪些未知、哪些有冲突。

## Trusted State View

Agent 做决策前拿到的一份紧凑的当前状态视图。每一项带一个可信度标记：

| 标记 | 含义 |
|---|---|
| **Confirmed** | 适当的权威来源已确认，注明确认主体、来源和时间；不代表绝对真理。 |
| **Inferred** | 由对话或工具证据推断，尚未确认；不会被默默升级为 Confirmed。 |
| **Unknown** | 信息缺失或无法核验；Agent 应承认不确定，而不是自行补全。 |
| **Conflicted** | 来源之间有冲突；按权限、来源优先级和确认流程处理，不靠猜。 |

每一项还记录时间、有效期、版本、来源/证据和权限。“已过期”可以和任一标记同时存在。

**“心中有数”不等于永远知道事实真相：状态有依据，但不保证一定为真。**

## 能力矩阵

| 能力 | 作用 | 状态 |
|---|---|---|
| State Tracking | 把目标、约束、计划、决策、承诺和关键进度变成明确对象 | 规划中 |
| State Updates | 根据新指令、工具结果和外部变化更新，保留版本及 superseded / effective 关系 | 规划中 |
| State Validation | 标记 Confirmed / Inferred / Unknown / Conflicted，识别过期，展示依据 | 规划中 |
| State Retrieval | 决策前返回紧凑、相关的 Trusted State View | 规划中 |
| 可信度标记 | Confirmed · Inferred · Unknown · Conflicted | 规划中 |
| API · MCP · SDK | 集成方式 | 规划中 |

只有附带可复现 Demo，状态才会更新为“部分实现”或“已实现并验证”。

## SaveSlot 不是什么

- **不是 Runtime、Checkpoint 或工作流引擎。** 不保存或恢复执行栈、进程状态和调度；这些工具可以与它配合使用。
- **不是真相裁决者。** 业务事实、规则和写入权归源系统，SaveSlot 不替代它们。
- **不授予写入权。** 读到状态，不代表 Agent 获得修改其他系统的权限。

## 路线图

- **P0**：单 Agent、单 Session，长任务和多步骤工具调用中的状态失真。
- **P1**：单 Agent 跨 Session；多个源系统的状态变化与冲突。
- **P2**：经授权的跨 Agent 共享，带版本的冲突处理。
