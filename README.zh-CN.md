# SaveSlot

[English](README.md) · **简体中文**

### 记得住，不代表记得对。

**让所有 AI 共享同一份准确、持续更新的信息。**

将散落在聊天记录和 AI 记忆中的重要信息，整理成结构清晰、持续更新、值得信赖的个人信息，让每个 AI 都能准确掌握。

SaveSlot 是一套开源的个人 Agent 持久状态基础设施，让不同 AI 可以在用户授权下，共同读取和更新目标、决策、任务及进展。

让每个 AI 都知道：什么已经完成，什么发生了变化，下一步应该做什么。

## 问题：AI 越来越记得你，却依然接不住你手上的事

- 昨天在 ChatGPT 讨论好的方案，今天换 Claude 又要重新交代。
- 一个 Agent 已经完成任务，另一个还以为没开始。
- AI 记得你的目标，却不知道完成到哪、哪个决定变了、下一步做什么。
- 项目、健康、财务、生活事务，散落在不同应用和聊天记录里。

**这不是记忆问题，而是持续性问题。**

## 记忆 → 状态 → 持续性

- **记忆**：AI 记住了关于你的什么。
- **状态**：事情实际进行到哪一步——目标、决策、任务、记录，保持准确和最新。
- **持续性**：每个 AI 都从同一份状态接着做，不必重新交代。

很多记忆工具已经能跨会话、跨 Agent 持久保存。SaveSlot 的区别在于核心对象：不是记忆或上下文，而是作为数据被持续维护的你的状态。

|          | 记忆层           | SaveSlot                       |
| -------- | ---------------- | ------------------------------ |
| 核心对象 | 记忆与上下文     | 你的状态：目标、决策、任务、记录 |
| 发生变化时 | 新增或更新一条记忆 | 更新记录，保留历史与来源         |
| 目标     | 找回合适的上下文 | 让每个 AI 基于同一份事实工作     |

## 同一份状态，不同的 Agent

**Agent A**

> 「设计方案已经通过，落地页也完成了，但发布邮件还没准备。」

**SaveSlot**

> 项目：产品上线<br>
> 设计：已通过<br>
> 落地页：已完成<br>
> 发布邮件：待处理

**Agent B**

> 「设计和落地页都完成了，我们接下来准备发布邮件。」

无需反复交代，也不会轻易丢失进展。

## 以用户的长期状态为中心

SaveSlot 的设计围绕五项原则：

- **持久化：** 事务状态不随一次 Agent 会话结束而消失。
- **跨 Agent 共享：** 获得授权的 AI 可以使用同一份当前状态。
- **结构化进展：** 将目标、决定、任务和下一步行动作为明确的数据对象。
- **变化可追溯：** 状态持续更新，重要变更有迹可循。
- **用户自主：** 长期个人状态独立于任何单一 Agent 平台。
