# SaveSlot

[English](README.md) · **简体中文**

### 记得住，不代表记得对。

**让所有 AI 共享同一份准确、持续更新的信息。**

将散落在聊天记录和 AI 记忆中的重要信息，整理成结构清晰、持续更新、值得信赖的个人信息，让每个 AI 都能准确掌握。

SaveSlot 是一套开源的个人 Agent 持久状态基础设施，让不同 AI 可以在用户授权下，共同读取和更新目标、决策、任务及进展。

让每个 AI 都知道：什么已经完成，什么发生了变化，下一步应该做什么。

## 问题：对话会结束，但事情不会。

每个 Agent 都有自己的上下文，但一个人的事务往往跨越多个对话、工具和模型。

你不应该每次换个 AI，就重新解释：

- 之前已经做了哪些决定
- 哪些任务已经完成
- 最近有哪些变化
- 接下来还要做什么

**这不只是记忆问题，而是事务无法连续推进的问题。**

## 不只是 Agent Memory

**Memory 关心：** AI 应该记住什么？

**SaveSlot 关心：** 事情现在进行到哪一步，接下来该做什么？

SaveSlot 以人的长期事务状态为核心，而不只是检索过去的对话和信息。

|          | 典型记忆场景      | SaveSlot 的设计重点      |
| -------- | ----------------- | ------------------------ |
| 核心问题 | 应该记住什么？    | 事情进行到哪一步？       |
| 核心数据 | 事实、偏好、上下文 | 目标、决策、任务、进展   |
| 更新重点 | 记住新信息        | 追踪变化与完成情况       |
| 最终目的 | 更准确地理解用户  | 让不同 Agent 接续工作    |

两者并不互斥。SaveSlot 选择将事务连续性作为首要设计目标。

## 同一份状态，不同的 Agent

**Agent A**

> 「设计方案已经通过，落地页也完成了，但发布邮件还没准备。」

**SaveSlot**

> 项目：产品上线<br>
> 设计：已通过<br>
> 落地页：已完成<br>
> 发布邮件：待处理

**Agent B**

> 「设计和落地页都完成了，我们接下来准备发布邮件。」

无需反复交代，也不会轻易丢失进展。

## 以用户的长期状态为中心

SaveSlot 的设计围绕五项原则：

- **持久化：** 事务状态不随一次 Agent 会话结束而消失。
- **跨 Agent 共享：** 获得授权的 AI 可以使用同一份当前状态。
- **结构化进展：** 将目标、决定、任务和下一步行动作为明确的数据对象。
- **变化可追溯：** 状态持续更新，重要变更有迹可循。
- **用户自主：** 长期个人状态独立于任何单一 Agent 平台。
